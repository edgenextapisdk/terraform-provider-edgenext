## Steps

### 1. Detect Changes

Run git diff to find changed files in the source project:

```bash
cd <source-project>
git status --porcelain
git diff --name-only HEAD~1  # or specify a commit range
```

Filter for SCDN/SDNS files only:
- `services/scdn/**`
- `services/sdns/**`
- `connectivity/scdn_client.go`
- Relevant `website/docs/**` files
- Relevant `examples/**` files

### 2. Analyze Minimal Changes

**IMPORTANT: Only sync the minimal changes required.**

For each changed file:
1. Get the actual diff content: `git diff HEAD~N -- <file>`
2. Analyze what specific lines/functions were modified
3. Check if the target file has the same content (after keyword replacement)
4. **Only sync if there are actual differences** - skip unchanged files

```bash
# Get detailed diff with context
git diff HEAD~N -- <file>

# For new files, check if they exist in target
ls -la <target-path>
```

**Minimal sync rules:**
- If only comments/descriptions changed → only sync documentation
- If only function body changed → only update that function
- If file is new → copy entire file with replacements
- If file is deleted in source → ask user about deletion
- If no meaningful changes after replacement → skip sync

### 3. Detect New Files (Source has, Target doesn't)

**IMPORTANT: Detect and sync new files that exist in source but not in target.**

This is critical for bringing new features from one provider to another:

```bash
# List files in source that don't exist in target
# For Go files:
ls src/services/scdn/security_protect/resource/*.go | while read f; do
  basename="$ (basename $f)"
  if [ ! -f "target/path/$basename" ]; then
    echo "NEW: $basename"
  fi
done
```

**New file handling:**
1. List all files in the source directory
2. Compare with target directory
3. For files that only exist in source:
   - Read the file content
   - Apply keyword replacements
   - Write to target location
   - Register in the resource map (if it's a resource/data source)

**New resource registration:**
If the new file is a resource or data source, you MUST also:
1. Update the module's registration file (e.g., `security_protect.go`)
2. Add the resource/data source to the appropriate map
3. Check if documentation needs to be created

### 4. Generate Sync List

### 3. Generate Sync List

Create a list of files to sync with their target paths:

```
## Sync List

| Source File | Target File | Status |
|-------------|-------------|--------|
| ...         | ...         | pending |

Status: pending / conflict / synced
```

### 3. Check for Conflicts

For each file to sync:
- Read the target file (if exists)
- Compare with source file (after keyword replacement)
- If both have changes in the same logic areas → mark as `conflict`

### 4. Handle Conflicts

When conflicts detected:
```
## ⚠️ Conflict Detected

**File**: <filename>
**Source**: <source-project>
**Target**: <target-project>

### Source Changes:
<source diff>

### Target Changes:
<target diff>

**Action Required**: Please review and decide how to resolve.
```

Use **AskUserQuestion tool** to get user decision:
- Overwrite target with source
- Skip this file
- Manual resolution (user will handle)

### 5. Execute Sync

For non-conflict files:
1. Read source file
2. Apply keyword replacements
3. Adjust import paths if needed
4. Write to target location
5. Mark as `synced`

### 6. Summary Report

```

**Direction**: <direction>
**Files Processed**: N
**Synced**: N
**Skipped**: N  
**Conflicts**: N (handed over to user)

### Synced Files:
- [x] file1.go
- [x] file2.go
```

## File Processing Rules

### Go Code Files (*.go)

1. **Package name**: Replace `package edgenext` ↔ `package byteshield`
2. **Import paths**: Replace full module path
3. **Function names**: 
   - `ResourceEdgenextScdn*` ↔ `ResourceByteshieldScdn*`
   - `DataSourceEdgenextScdn*` ↔ `DataSourceByteshieldScdn*`
   - `ResourceEdgenextSdns*` ↔ `ResourceByteshieldSdns*`
   - `DataSourceEdgenextSdns*` ↔ `DataSourceByteshieldSdns*`
4. **Resource names in schema**:
   - `"edgenext_scdn_*"` ↔ `"byteshield_scdn_*"`
   - `"edgenext_sdns_*"` ↔ `"byteshield_sdns_*"`
5. **Client types**:
   - `EdgeNextClient` ↔ `ByteShieldClient`
   - Note: EdgeNext has additional clients (APIClient, OSSClient, ECSClient) - DO NOT sync these

### Documentation Files (*.md)

1. Replace all keyword occurrences
2. Update resource/data source names in examples
3. Update provider configuration examples

### Example Files (*.tf)

1. Replace provider name: `provider "edgenext"` ↔ `provider "byteshield"`
2. Replace resource names
3. Update variable references if any
